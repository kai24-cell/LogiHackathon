## 検索と暫定判断

- 特徴語はファイル名、package、型・フィールド・メソッドの識別子、annotation、参照型、コメントから取得。英字は小文字化、camel/snake case分割、原識別子も保持する。日本語連続部分はcode point単位の2gram、1文字はそのまま。NFKCを表記ゆれの暫定正規化に使う。翻訳・日英辞書・Embeddingはない。
- 文書は全メソッドの仮チャンク。型・フィールドなどの宣言情報を各チャンクに付ける。メソッドなし・構文解析失敗はファイルの補助チャンクにする。ファイルのcosineは最大チャンク値、同点なら元の行順とする。idfは質問・主選択で変えない。
- `tf=1+ln(count)`（出現なしは0）、`idf=ln((N+1)/(df+1))+1`、積をL2正規化。質問だけにある語を加えず、ゼロベクトルとのcosineは0。
- 既存の方向付き依存をファイルへ投影し、関連探索だけ無向化して複数起点BFS。自己・1hopはdependency=1、2hopは0.5、その他は0。未解決参照は辺にしない。元の解析結果は変更しない。
- `R=0.50*C+0.30*D+0.20*F`。C=cosine、D=dependency、F=roleFitは各0〜1。係数は非負・合計1、有限値を起動時に検証する。`SearchScoring`に式を集約し、`cheapreview.search.*-weight`で変更する。暫定式であり比較実験で調整する。
- 例：C=0.4、D=1、F=0.5なら寄与0.20+0.30+0.10、総合0.60。質問に一致しなくてもD/Fで順位が付くが、意味的一致・回答品質の保証ではない。
- roleFitは設計書9.4の4観点の表を適用。CLASS_EXPLAINはファイル主選択をtargetとし、2hop内の型を関連型とする。AUTH_ANALYSISのユーザー関連Serviceはuser/account識別子を保守的な暫定根拠とする。質問の特定文言に応じて順位を調整しない。
- 同点はdependency→cosine→relativePath→beginLine。主選択は順位とは独立したフラグで保持し、全走査候補を返す。0点候補には一致なしと表示する。候補の予算選択・送信・生成は後続Issue。
- 最大質問10,000 code points、索引保持数初期値1は入力処理とメモリ使用を制限する暫定値。保持から外れたsnapshotも固定データから同じ索引を再構成する。設定ファイルはファイル名のみ。走査対象外・変更後のコードを読み直さない。
- 固定の質問と期待ファイルはサンプルの呼出し経路・責務から人手で定めた。順位・数値を正解へコピーしていない。係数変更後にも同じfixtureで比較できる。
